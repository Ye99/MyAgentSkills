# Prune Dev Files from a Home Backup

Shrink a home-folder copy to what the person made. Anything that can be downloaded again or rebuilt goes. Work that exists nowhere else is saved as plain files first, and then its container can go too.

**Core rule:** the test for each path is "can this be downloaded again or regenerated?" It is not "might someone want it?" If yes, delete it. If no, keep it. If it contains both kinds, rescue the part that can't be regenerated, then apply the test again.

## Workflow

`scripts/` is relative to this skill directory. HOME is the folder being pruned.

1. **Survey.** Run `du -sh HOME/.[!.]* HOME/* | sort -h`, then drill into everything over about 50 MB, including `.config`, `.local/share`, `snap`, `Downloads` and the Trash. Look inside a folder before you classify it.
2. **Save rebuild manifests:** `bash scripts/save_env_manifests.sh HOME HOME/RebuildManifests`. An environment can only be rebuilt if its package list survives.
3. **Rescue git work.** For every `.git` under HOME (Trash and Downloads included), run `bash scripts/rescue_git_work.sh HOME REPO`. It saves unpushed commits, stashes, uncommitted edits and untracked source files to `HOME/RescuedGitWork/` as patches plus file copies, with restore steps in a `README.txt`. Untracked build output is skipped. Its first line, `owner: person|third-party|unknown`, feeds the repo rows of the table.
4. **Show the plan if the user can answer.** Give one list grouped by the table rows below, with sizes, and get a single go-ahead. If the user is away, apply the table as written.
5. **Delete**, then remove empty folders without entering `.git`: `find HOME -name .git -prune -o -type d -empty -print -delete`.
6. **Verify.** Measure the "before" size in step 1. Re-list the paths you classified as Keep in step 1 and confirm each one still exists. Check that every rescued repo's `README.txt` is present. Test each remaining archive with `unzip -t` or `tar -tf`. Report the apparent size before and after, using `du -sb`.
7. **Report.** Cover what was deleted, grouped by table row; what was kept; any archives that won't open; and any private keys or credential files kept in the archive (such as `.ssh`), so the person can encrypt it.

## Classification

| Path | Action |
|---|---|
| Toolchains and SDKs: `anaconda3`, `miniconda3`, `.conda`, `.nvm`, `.npm`, `.pyenv`, `.rustup`, `.cargo/registry`, `Android/Sdk`, `.android/avd`, `.gradle`, `.m2`, `.conan`, `go/pkg` | Delete |
| Envs and dependencies: `node_modules`, `.venv`, `venv`, `site-packages`, `Pods` | Delete, after step 2 |
| Editors and apps: `.vscode/extensions`, `.cursor`, JetBrains plugin data, IDE folders in `apps/` or `Downloads`, `.oh-my-zsh`, AppImages, `.deb`, `.run`, installer `.sh`, IDE `.tar.gz`, an unpacked installer next to its archive, launchers in `.local/share/applications` that point at deleted apps | Delete |
| Caches: `.cache`, `__pycache__`, `.pytest_cache`, `.ipynb_checkpoints`, browser `Cache`, `Code Cache`, `GPUCache` and `Service Worker`, browser site storage (`IndexedDB`, `File System`), browser component stores (`optimization_guide_model_store`, `component_crx_cache`, `screen_ai`, `Safe Browsing`), `.zcompdump*`, editor `CachedData`, `*.backup` copies of editor state | Delete |
| Tool leftovers: IDE project state (`.idea`, `.vs`), path lists for deleted tools (`.conda/environments.txt`), Trash `info/*.trashinfo` whose file is gone | Delete |
| Compiled results, intermediate or final: `build`, `dist`, `out`, `target`, `.next`, `.cxx`, `*.o`, `*.so`, `*.pyc`, `*.class`, `*.dex`, `*.apk`, `*.aab`, `*.map`, `gradle-wrapper.jar` (regenerated by `gradle wrapper`; keep the `.properties`) | Delete |
| Downloaded models: `.lmstudio/models`, `.ollama/models`, `~/.cache/huggingface` | Delete |
| Public downloads: YouTube `videoplayback*`, DOI datasets (`doi_10_*`), published books and papers, stock photos, xeno-canto `XC*` recordings | Delete |
| The person's own project, `owner: person` (or `unknown` but outside Trash and Downloads): the main working copy | Keep the working tree. Delete only `.git`, after step 3. |
| Extra copies: a clone in Trash or Downloads, or a second copy of a remote whose main copy is kept | Delete the whole folder, after step 3 |
| Third-party clones, `owner: third-party` | Delete the whole folder, after step 3 |
| Duplicates: byte-identical files (`jdupes -r`, but never touching `RescuedGitWork` or `RebuildManifests`), and a folder unpacked from a zip that sits next to it | Keep one: the copy outside Trash, without ` (n)`, with the shortest path. For a zip and its unpacked folder, keep the zip if `unzip -l` matches the folder. |
| The person's files anywhere, Trash included: documents, photos, media, data, notebooks, source, archives they made, and any archive that won't open | Keep. List archives that won't open in the report. |
| Settings and identity: dotfiles, `.ssh`, `.gnupg`, app config, browser `Bookmarks`, `History`, `Preferences`, LM Studio `conversations`, editor `User/settings.json` and `state.vscdb` (chat history) | Keep |

## Excuses that keep junk

| Excuse | Reality |
|---|---|
| "gradle-wrapper.jar is tracked in the repo" | Being tracked doesn't make it source. `gradle wrapper` rebuilds it from the `.properties` file. |
| "The repo has unpushed work, so `.git` stays" | That's what step 3 is for. The patches keep the work; `.git` is only the container. |
| "Any clone can go once it's rescued, including the main project" | Only extra copies and third-party clones go whole. For the person's own project, keep the tree so the archive opens as a folder; `.git` is the only part that goes. |
| "This Trash copy has an edit found nowhere else" | Rescue it, then delete the copy. The Trash's own user files stay. |
| "The YouTube video might be taken down" or "Site storage might hold web-app projects" | Public downloads and browser storage can be regenerated. The person can export anything they want from the web app. |
| "Duplicates weren't part of the request" | An exact copy can be recreated from the kept copy. Keep one. |
| "The zip can't be confirmed to match the folder" | Run `unzip -l` and compare. If they match, the folder goes. If they differ, keep both and say so in the report. |
| "I deleted the env without listing its packages" | Then it can't be rebuilt. Always run step 2 first. |
