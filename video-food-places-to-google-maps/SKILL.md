# Video food places to Google Maps

Start with the video's description for stall names and addresses. If it omits them, use stall names shown on screen at each transition as primary leads. Locate transitions efficiently: sample separated timestamps, bracket each change of stall, then narrow that interval by binary search until a name card or storefront sign is readable. Record the video's timestamp and corroborate the exact name with the current Maps listing; do not infer a stall from food alone. If on-screen names do not cover every stop, check for a timestamped viewer comment that lists the rest. Treat viewer comments as leads, not as the creator's recommendations or proof of a business identity: corroborate each name and timestamp with the video when practical, then match the name and location to a current Maps listing. Use the Maps address when the video supplies none, and label that provenance in the travel note. If a comment names a stall but its Maps identity or current listing cannot be verified, record it as unresolved and do not save a guessed match. If captions or a transcript are readily available, use them to identify ordered dishes and actual recommendations. Check any closing summary for a ranked or recommended subset. Distinguish that subset from stalls merely visited, and put the creator's recommendation or rank in each matching Google Maps saved note. When the video compares two or more similar stalls and explicitly prefers one, add a concise comparison to the saved note for **each** matched stall: mark the preferred stall as recommended over the named alternative, and mark the other as not recommended relative to the preferred stall. Cite the video and timestamp when available. Do not infer a negative verdict from a ranking or from silence; use the not-recommended label only when the creator actually makes that comparison. If neither captions nor transcript is available, skip flavor and endorsement research; record only food plainly identifiable from the stall name or a frame already inspected, and label uncertainty.

For each distinct place, match the name **and address** against its current Google Maps listing. Read the live rating, review count, and closure status. Do not save a place marked permanently closed. If a listing has moved or its address differs, resolve the identity before saving; keep an unresolved entry in the note without a Maps save. Before clicking Save, inspect the place's current list membership. If it is already in the requested list, **do not click the Save or list checkbox again**: those controls can toggle membership off. Leave it saved and only add the new video mention or recommendation to its existing Maps note. For an unsaved eligible place, save it once in the requested list and verify membership afterward. Add a short Maps note with the identified food and video URL or timestamp. Do not overwrite an existing Maps note; append only if it remains readable.

In the travel note, keep one row per place with address, identified food, source video link, Maps rating and review count with check date, and saved/closed/unresolved status. Add later videos to the same place's source cell so repeated mentions remain visible. Preserve concurrent note edits with a narrow insertion. After editing a Maps note, wait until Google Maps changes the field from Add note to Edit note, then reopen the listing and verify both Taiwan membership and the full new note; navigating away before autosave finishes can silently lose the note. Never use the Save button as a verification step. Check the travel-note diff before reporting totals. Count newly saved places separately from already saved, closed, and unresolved places.
